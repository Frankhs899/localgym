This file is the authority for the debt ids it consolidates — L35, L39, L41, L42, L43, L45 and L47 of `odd/tasks/design-system.md` — and it adds nothing those entries did not record, except where the owner settles a product decision (S1).

## Specs

- **S1** — The owner's request, verbatim: "Crea una nueva rama para solucionar lo de field.js compartido (R2-001 + R2-002), decisión de UX de R3-002, label "Mostrar/Ocultar", advisories de design/tools/probe.mjs y el doble build del job de CI." The three settled answers, verbatim: "Limpiar el error del campo al tipear", "Label dinámico Mostrar/Ocultar", "Sí, paridad con Login". They are the product decision behind S5, S6 and S7 and are not open to re-derivation.
- **S2** — The field control lives in one module, `frontend/src/components/field.jsx` (planned; L42/L47 name it `field.js`), imported by `pages/Login.jsx` and `pages/Perfil.jsx`; after T1 and T2 neither page defines `fieldClass` or `fieldBorder`, which today are byte-identical (`Login.jsx:14-15`, `Perfil.jsx:13-14`) and the same ternary formatted two ways (`Login.jsx:17-18`, `Perfil.jsx:16`). The module owns the class contract (`min-h-[36px]` plus the `leading-4` 16 px line-height that makes the min-height bind, `border-line-strong` normally and `border-danger` when invalid, the panel surface, the text tier), the per-field `invalid` flag, the invalid wiring (`aria-invalid` and `aria-describedby` pointing at that field's error id), and the error node itself: `role="alert"`, the per-field id, and the messages it is given.
- **S3** — Login keeps the deliberate deviation of L38, recorded as `R3-002`/L39: one server message marks **both** fields invalid (`Login.jsx:44-47`) and one node carries the whole statement, `#login-error` with `role="alert"` and the icon (`Login.jsx:149-151`), with both fields describing it. Nothing in this feature reduces that to a per-field server message; only the clearing rule (S7) splits the single boolean, which no clearing rule can avoid.
- **S4** — Mi perfil keeps one error node per field with its own id — `perfil-current-error` (`Perfil.jsx:140`) and `perfil-new-error` (`Perfil.jsx:165`) — and each now carries `role="alert"` (neither does today) and renders **every** message the backend returned for that field joined with one space. Today the current-password field renders only the first message (`Perfil.jsx:141`) while the new-password field joins them (`Perfil.jsx:166`); one node owner removes that difference. Decision (approved): the `[0]` truncation is dropped on purpose — one node owner, one shape. The form-level failure keeps its own `role="alert"` node (`Perfil.jsx:172`) and the success line keeps `role="status"` (`Perfil.jsx:177`).
- **S5** — The reveal control has one implementation, in the S2 module, and is rendered on Login's password field (`Login.jsx:133-145`) and on both Mi perfil password fields (owner: "Sí, paridad con Login"). It toggles the `type` of the field it controls between `password` and `text`, names that field with `aria-controls`, keeps `aria-pressed` as the state, shows "Mostrar" while hidden and "Ocultar" while shown, and its `aria-label` follows the visible label ("Mostrar contraseña" / "Ocultar contraseña"). Checked live on all three password fields: text, `aria-label`, `aria-pressed` and `type` change together and back.
- **S6** — The password field reserves room for that control with a token-derived `calc()` on its right padding — today `pr-[calc(var(--spacing-hero)+var(--spacing-page)+var(--spacing-tight))]`, 84 px (`Login.jsx:130`; the three tokens at `frontend/src/index.css:116,121-122`) — and the declaration carries a comment stating what it reserves and that it must be re-measured when the label, the font or the control changes (`R2-magic-pr-padding`/L39). Checked in **both** label states on both screens: the field's painted right padding is at least the control's painted width plus `--spacing-tight`, so typed text cannot run under it.
- **S7** — Typing in a field clears **that** field's error as the value changes: the danger border becomes `border-line-strong`, `aria-invalid` and `aria-describedby` stop asserting invalidity, and that field's message node disappears. Nothing else changes: the other field keeps its error in all three places, the form-level server message stays (Login's single `#login-error` while the other field is still invalid, Perfil's node at `Perfil.jsx:172`), and the success line (`Perfil.jsx:177`) keeps its current behaviour, untouched by this rule. Submitting still clears the previous errors before the request (`Login.jsx:31`, `Perfil.jsx:53-54`). Decision (approved): Login's single boolean becomes one flag per field; the single shared message stays. This closes the stale danger borders of `R3-002`/L41, whose state outlived the value that produced it.
- **S8** — `R3-002` names two different findings in `odd/tasks/design-system.md`: L39 item 5 (`aria-invalid` on both Login fields can assert an invalidity that is false for one of them) and L41 (stale danger borders keyed off `fieldErrors`). This feature acts on the **second only**, through S7, and cites it as `R3-002`/L41; the first stays the deliberate deviation S3 preserves and is cited as `R3-002`/L39. No entry is renumbered and every reference here carries its log id. Same adjudication for the other collision: `R3-001`/L41 (the field contract asserted nowhere) is closed by the runner in L44, while `R3-001`/L39 (the static reveal label) is what S5 acts on.
- **S9** — `design/tools/probe.mjs` refuses to overwrite a file at `._probe_<artboard>` that it cannot prove it wrote. The marker is not proof: a foreign file that merely contains `gentle-design-probe-copy` (`probe.mjs:72`) — which is what an artboard documenting the tool looks like — is refused, exit 2, stderr naming the file, bytes unchanged (`R1-overwrite-marker`/L35). The copy is written atomically: a temporary file in the same directory, then a rename over the destination (`probe.mjs:155` is a plain `writeFileSync` today), so a run killed mid-write leaves either the previous state or the complete copy, never a truncated file that the next run classifies as foreign and refuses forever (`R4-1`/L35). A normal run leaves no temporary file behind, and a run killed during the probe is followed by a run that succeeds with no manual deletion.
- **S10** — The frontend CI job compiles the SPA exactly once: `Build` (`.github/workflows/ci.yml:84-85`) still runs first, so a broken build fails the job before any probe, and `Design contract tests` (`:90-91`) runs the probes without compiling again. `pnpm test` keeps its local meaning — build once, then probe (`frontend/package.json:12`, documented at `README.md:117`) — because the probes must only ever measure the build that was just produced.
- **S11** — The design-contract suite (`frontend/tests/design-contract.spec.js`) keeps P1-P3 (`:103`, `:137`, `:162`) green on Login and Mi perfil and gains one probe per new behaviour, set up through the `/api/me/` stub the suite already uses (`:20-38`): **S5** — pressing the reveal control on each of the three password fields flips `type`, `aria-pressed`, the visible label and `aria-label` together, then back; **S7** — a failed submit marks both Login fields invalid, typing in one clears only that field's border, `aria-invalid` and `aria-describedby` while the other field's error and `#login-error` stay, and typing in the second removes the node; on Mi perfil the same with `perfil-current`/`perfil-new` while the form-level node stays; **S6** — for both label states on both screens the field's right padding clears the control's width plus `--spacing-tight`. Login's failure is stubbed on `/api/auth/login/` and Mi perfil's on `/api/me/password/` (`frontend/src/auth.jsx:41`, `:61`).
- **S12** — The docs state the contract where a reader looks. `design/system.md`: the `Input` rule (`:161`) names the 36 px / 16 px pairing, the absence of `outline-none` and the danger border for invalid; a new reveal rule states the dynamic label, the kept `aria-pressed` and that the reserved padding tracks the label; the `Known Gaps` line "Estados no documentados" (`:206`) no longer lists per-field validation error, because the contract is now documented and asserted. `frontend/README.md` lists the new probes next to P1-P3 (`:3-12`).
- **S13** — Nothing painted regresses: on Login and Mi perfil P1-P3 stay green — field 36 px with a 16 px line-height, keyboard focus paints the 2 px accent ring (`#EFFF00`), typed text resolves to `--color-text` and clears 4.5:1 against the field's painted background — and neither screen gains horizontal overflow at 500, 768 or 1440 px.
